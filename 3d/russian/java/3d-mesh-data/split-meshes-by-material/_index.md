# Как разделить сетку по материалу в Java с использованием Aspose.3D

## Введение

Если вы работаете с 3D‑графикой в Java, быстро обнаружите, что обработка больших сеток может стать узким местом производительности — особенно когда одна сетка содержит несколько материалов. **Изучение того, как разделить сетку** по материалу позволяет изолировать каждую группу полигонов, специфичную для материала, обеспечивая более быструю отрисовку, упрощённое отсечение и более детальный контроль над текстурами. В этом руководстве мы пошагово рассмотрим, как **разделить сетку по материалу** с помощью библиотеки Aspose.3D, включая практические объяснения, советы по уменьшению количества вызовов отрисовки и рекомендации по повышению производительности рендеринга.

## Быстрые ответы
- **Что означает «разделить сетку по материалу»?** Это разделяет одну сетку на несколько под‑сеток, каждая из которых содержит полигоны, использующие один и тот же материал.  
- **Зачем использовать Aspose.3D?** Он предоставляет высокоуровневый, кроссплатформенный API, который абстрагирует низкоуровневые форматы файлов, сохраняя при этом производительность.  
- **Сколько времени занимает реализация?** Около 10–15 минут кодирования и тестирования.  
- **Нужна ли лицензия?** Доступна бесплатная пробная версия; коммерческая лицензия требуется для использования в продакшене.  
- **Какая версия Java поддерживается?** Java 8 или выше.

## Что такое разделение сетки?

`Mesh splitting` — процесс деления сложной 3D‑сетки на более мелкие, удобные части. Когда разделение основано на материале, каждая полученная под‑сетка содержит только полигоны, ссылающиеся на один материал. Такой подход уменьшает количество вызовов отрисовки, повышает производительность рендеринга и упрощает задачи, такие как применение шейдеров per‑material.

## Как разделение уменьшает количество вызовов отрисовки?

Разделение сетки создаёт одну под‑сетку на каждый материал, позволяя графическому движку выполнить один вызов отрисовки для каждого материала вместо одного на каждый полигон. Меньшее количество вызовов отрисовки означает меньше переключений состояний GPU, что напрямую приводит к более высоким FPS как на настольных, так и на мобильных GPU.

## Почему разделять сетку по материалу?

Разделение сетки по материалу улучшает производительность, поскольку рендерер может пакетировать вызовы отрисовки для каждого материала, уменьшая переключения состояний GPU. Это также даёт разработчикам гибкость применять разные шейдеры, пост‑процессинговые эффекты или логику столкновений для каждого материала. Кроме того, более мелкие под‑сетки легче стримить, управлять памятью и отсеивать, что особенно ценно на мобильных, AR и VR платформах.

## Количественные преимущества Aspose.3D

Aspose.3D поддерживает **более 30 форматов ввода и вывода** — включая OBJ, FBX, STL и GLTF — и может обрабатывать сетки с **до 10 млн полигонов** без загрузки всего файла в память. Использование политики разделения `COMPACT_DATA` может сократить использование памяти под вершины **до 40 %**, что особенно ценно для Java 3D‑графики на устройствах с низкой производительностью.

## Импорт пакетов

`Scene` — корневой объект Aspose.3D, содержащий все узлы, источники света и камеры в 3D‑сцене.  
`Mesh` представляет геометрические данные — вершины, ребра и грани — 3D‑объекта.  
`VertexElementMaterial` хранит целочисленный индекс материала для каждого полигона, позволяя назначать материал per‑polygon.  
`PolygonModifier` предоставляет статические методы для редактирования сеток, такие как разделение или объединение полигонов.  

Класс `Scene` представляет контейнер 3D‑сцены, а `Mesh` хранит данные геометрии; `VertexElementMaterial` хранит индексы материалов per‑polygon, а `PolygonModifier` предоставляет утилиты для манипуляций сеткой.

import com.aspose.threed.*;

## Пошаговое руководство

Ниже представлена лаконичная пошаговая инструкция, где объяснения идут перед каждым заполнителем, чтобы вы точно знали, что происходит.

### Шаг 1: Создать сетку коробки

Класс `Box` создаёт геометрию куба с шестью гранями, каждая из которых представлена отдельным полигоном. Мы начинаем с простого геометрического примитива — коробки — чтобы чётко увидеть, как каждая грань (плоскость) получит свой материал позже.  
```java
// ExStart:SplitMeshbyMaterial

// Create a mesh of a box (composed of 6 planes)
Mesh box = (new Box()).toMesh();
```

### Шаг 2: Создать элемент материала

`VertexElementMaterial` хранит индексы материалов для каждого полигона. Присоединив его к сетке, мы можем управлять тем, какой материал использует каждая грань.  
```java
// Create a material element on the box mesh
VertexElementMaterial mat = (VertexElementMaterial) box.createElement(VertexElementType.MATERIAL, MappingMode.POLYGON, ReferenceMode.INDEX);
```

### Шаг 3: Указать разные индексы материалов

Здесь мы присваиваем уникальный индекс материала каждой из шести плоскостей коробки. Порядок массива соответствует порядку полигонов, генерируемых примитивом `Box`.  
```java
// Specify different material indices for each plane
mat.setIndices(new int[]{0, 1, 2, 3, 4, 5});
```

### Шаг 4: Разделить сетку на под‑сети

Перечисление `SplitMeshPolicy` определяет, как обрабатываются данные вершин при разделении, например `CLONE_DATA` или `COMPACT_DATA`. Вызов `PolygonModifier.splitMesh` с `SplitMeshPolicy.CLONE_DATA` создаёт новую под‑сетку для каждого уникального индекса материала, сохраняя оригинальные данные вершин.  
```java
// Split the mesh into 6 sub-meshes, each plane becoming a sub-mesh
Mesh[] planes = PolygonModifier.splitMesh(box, SplitMeshPolicy.CLONE_DATA);
```

### Шаг 5: Обновить индексы материалов и разделить снова

Чтобы продемонстрировать другую стратегию разделения, мы теперь группируем первые три плоскости под материал 0, а оставшиеся три — под материал 1, затем разделяем с помощью `COMPACT_DATA`, чтобы удалить неиспользуемые вершины.  
```java
// Update material indices and split into 2 sub-meshes
mat.getIndices().clear();
mat.setIndices(new int[]{0, 0, 0, 1, 1, 1});
planes = PolygonModifier.splitMesh(box, SplitMeshPolicy.COMPACT_DATA);
```

### Шаг 6: Подтвердить успех

Простое сообщение в консоли сообщает, что операция завершилась без ошибок.  
```java
// Display success message
System.out.println("\nSplitting a mesh by specifying the material successfully.");
// ExEnd:SplitMeshbyMaterial
```

## Сократить количество вызовов отрисовки и улучшить производительность рендеринга

Превратив каждый материал в отдельную сетку, вы позволяете графическому конвейеру выполнить один вызов отрисовки на материал вместо одного на каждый полигон. Такое сокращение количества вызовов напрямую приводит к более плавным кадрам, особенно на слабом оборудовании. Кроме того, политика `COMPACT_DATA` удаляет неиспользуемые вершины, дополнительно снижая пропускную способность памяти и помогая GPU рендерить эффективнее.

## Распространённые проблемы и решения

| Проблема | Почему происходит | Решение |
|----------|-------------------|---------|
| **Под‑сети содержат дублирующие вершины** | Использование `CLONE_DATA` копирует все данные вершин для каждой под‑сети. | Перейдите на `COMPACT_DATA`, если хотите удалить дублирующиеся вершины. |
| **Неправильное назначение материала** | Длина массива индексов не соответствует количеству полигонов. | Проверьте количество полигонов (например, у коробки их 6) и предоставьте соответствующий массив индексов. |

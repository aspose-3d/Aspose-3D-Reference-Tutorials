# Как разделить сетку по материалу в Java с использованием Aspose.3D

## Введение

Если вы работаете с 3D‑графикой в Java, вы быстро обнаружите, что обработка больших сеток может стать узким местом производительности — особенно когда одна сетка содержит несколько материалов. **Изучение того, как разделить сетку** по материалу позволяет изолировать каждую группу полигонов, специфичную для материала, обеспечивая более быструю отрисовку, более простое отсечение и более детальный контроль над обработкой текстур. В этом руководстве мы пройдем точные шаги по **разделению сетки по материалу** с использованием библиотеки Aspose.3D, предоставив практические объяснения, советы по уменьшению количества вызовов отрисовки и рекомендации по повышению производительности рендеринга.

## Быстрые ответы
- **Что означает «разделить сетку по материалу»?** Это разделяет одну сетку на несколько под‑сеток, каждая из которых содержит полигоны, использующие один и тот же материал.  
- **Почему использовать Aspose.3D?** Он предоставляет высокоуровневый кроссплатформенный API, который абстрагирует низкоуровневые форматы файлов, сохраняя при этом производительность.  
- **Сколько времени занимает реализация?** Около 10–15 минут кодирования и тестирования.  
- **Нужна ли лицензия?** Доступна бесплатная пробная версия; коммерческая лицензия требуется для использования в продакшене.  
- **Какая версия Java поддерживается?** Java 8 или выше.

## Что такое разделение сетки?

`Mesh splitting` — процесс разделения сложной 3D‑сетки на более мелкие, управляемые части. Когда разделение основано на материале, каждая получающаяся под‑сетка содержит только полигоны, ссылающиеся на один материал. Такой подход уменьшает количество вызовов отрисовки, повышает производительность рендеринга и упрощает задачи, такие как применение шейдеров per‑material.

## Как разделение уменьшает количество вызовов отрисовки?

Разделение сетки создает одну под‑сетку на каждый материал, позволяя графическому движку выполнить один вызов отрисовки для каждого материала вместо одного на каждый полигон. Меньшее количество вызовов отрисовки означает меньше изменений состояния GPU, что напрямую приводит к более высоким частотам кадров как на настольных, так и на ограниченных мобильных GPU.

## Зачем разделять сетку по материалу?

Разделение сетки по материалу улучшает производительность, потому что рендерер может пакетировать вызовы отрисовки для каждого материала, уменьшая изменения состояния GPU. Это также дает разработчикам гибкость применять отдельные шейдеры, постобработку или логику столкновений для каждого материала. Кроме того, более мелкие под‑сетки легче стримить, управлять памятью и отсеивать, что особенно ценно на мобильных, AR и VR платформах.

## Количественные преимущества Aspose.3D

Aspose.3D поддерживает **30+ форматов ввода и вывода** — включая OBJ, FBX, STL и GLTF — и может обрабатывать сетки с **до 10 млн полигонов** без загрузки всего файла в память. Использование политики разделения `COMPACT_DATA` может сократить использование памяти под вершины **до 40 %**, что особенно ценно для Java 3D‑графики на устройствах с низкой производительностью.

## Пошаговое руководство

Ниже представлена краткая пошаговая инструкция, с объяснениями перед каждым заполнителем, чтобы вы точно знали, что происходит.

### Шаг 1: Создать сетку коробки

Класс `Box` создает геометрию куба с шестью гранями, каждая из которых представлена отдельным полигоном. Мы начинаем с простого геометрического примитива — коробки, чтобы ясно увидеть, как каждая грань (плоскость) получит свой материал позже.  
```java
// ExStart:SplitMeshbyMaterial

// Create a mesh of a box (composed of 6 planes)
Mesh box = (new Box()).toMesh();
```

### Шаг 2: Создать элемент материала

`VertexElementMaterial` сохраняет индексы материалов для каждого полигона. При присоединении его к сетке мы можем контролировать, какой материал использует каждая грань.  
```java
// Create a material element on the box mesh
VertexElementMaterial mat = (VertexElementMaterial) box.createElement(VertexElementType.MATERIAL, MappingMode.POLYGON, ReferenceMode.INDEX);
```

### Шаг 3: Указать разные индексы материалов

Здесь мы назначаем уникальный индекс материала каждой из шести плоскостей коробки. Порядок массива соответствует порядку полигонов, генерируемых примитивом `Box`.  
```java
// Specify different material indices for each plane
mat.setIndices(new int[]{0, 1, 2, 3, 4, 5});
```

### Шаг 4: Разделить сетку на под‑сетки

Перечисление `SplitMeshPolicy` определяет, как обрабатываются данные вершин при разделении, например, `CLONE_DATA` или `COMPACT_DATA`. Вызов `PolygonModifier.splitMesh` с `SplitMeshPolicy.CLONE_DATA` создаёт новую под‑сетку для каждого отдельного индекса материала, сохраняя оригинальные данные вершин.  
```java
// Split the mesh into 6 sub-meshes, each plane becoming a sub-mesh
Mesh[] planes = PolygonModifier.splitMesh(box, SplitMeshPolicy.CLONE_DATA);
```

### Шаг 5: Обновить индексы материалов и разделить снова

Чтобы продемонстрировать другую стратегию разделения, мы теперь группируем первые три плоскости под материал 0, а оставшиеся три — под материал 1, затем разделяем с помощью `COMPACT_DATA`, чтобы удалить неиспользуемые вершины.  
```java
// Update material indices and split into 2 sub-meshes
mat.getIndices().clear();
mat.setIndices(new int[]{0, 0, 0, 1, 1, 1});
planes = PolygonModifier.splitMesh(box, SplitMeshPolicy.COMPACT_DATA);
```

### Шаг 6: Подтвердить успех

Простое сообщение в консоли сообщает, что операция завершилась без ошибок.  
```java
// Display success message
System.out.println("\nSplitting a mesh by specifying the material successfully.");
// ExEnd:SplitMeshbyMaterial
```

## Сократите количество вызовов отрисовки и улучшите производительность рендеринга

Превращая каждый материал в отдельную сетку, вы позволяете графическому конвейеру выполнить один вызов отрисовки на материал вместо одного на каждый полигон. Это сокращение количества вызовов напрямую приводит к более плавным частотам кадров, особенно на слабом оборудовании. Кроме того, политика `COMPACT_DATA` удаляет неиспользуемые вершины, дополнительно снижая пропускную способность памяти и помогая GPU рендерить более эффективно.

## Распространённые проблемы и решения

| Проблема | Почему происходит | Решение |
|----------|-------------------|---------|
| **Под‑сетки содержат дублирующие вершины** | Использование `CLONE_DATA` копирует все данные вершин для каждой под‑сетки. | Перейдите на `COMPACT_DATA`, если хотите, чтобы общие вершины были дедуплицированы. |
| **Неправильное назначение материала** | Длина массива индексов не соответствует количеству полигонов. | Проверьте количество полигонов (например, у коробки их 6) и предоставьте соответствующий массив индексов. |

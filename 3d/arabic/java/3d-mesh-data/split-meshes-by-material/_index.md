# كيفية تقسيم الشبكة حسب المادة في Java باستخدام Aspose.3D

## مقدمة

إذا كنت تعمل مع رسومات ثلاثية الأبعاد في Java، ستكتشف بسرعة أن معالجة الشبكات الكبيرة يمكن أن تصبح عنق زجاجة في الأداء—خاصة عندما تحتوي شبكة واحدة على مواد متعددة. **تعلم كيفية تقسيم الشبكة** حسب المادة يتيح لك عزل كل مجموعة من المضلعات الخاصة بالمادة، مما يتيح عرضًا أسرع، وإزالة غير مرئية أسهل، وتحكمًا أكثر تفصيلًا في معالجة القوام. في هذا البرنامج التعليمي سنستعرض الخطوات الدقيقة **لتقسيم الشبكة حسب المادة** باستخدام مكتبة Aspose.3D، مع شروحات عملية، ونصائح لتقليل استدعاءات الرسم، ونصائح لتحسين أداء العرض.

## إجابات سريعة
- **ما معنى “تقسيم الشبكة حسب المادة”؟** يفصل شبكة واحدة إلى عدة شبكات فرعية، كل منها يحتوي على مضلعات تشترك في نفس المادة.  
- **لماذا نستخدم Aspose.3D؟** يوفر واجهة برمجة تطبيقات عالية المستوى ومتعددة المنصات تُجرد صيغ الملفات منخفضة المستوى مع الحفاظ على الأداء.  
- **كم من الوقت تستغرق التنفيذ؟** تقريبًا 10–15 دقيقة من البرمجة والاختبار.  
- **هل أحتاج إلى ترخيص؟** نسخة تجريبية مجانية متاحة؛ يلزم ترخيص تجاري للاستخدام في الإنتاج.  
- **ما نسخة Java المدعومة؟** Java 8 أو أعلى.

## ما هو تقسيم الشبكة؟

`Mesh splitting` هو عملية تقسيم شبكة ثلاثية الأبعاد معقدة إلى قطع أصغر وأكثر قابلية للإدارة. عندما يكون التقسيم مبنيًا على المادة، يحتوي كل شبكة فرعية ناتجة فقط على المضلعات التي تشير إلى مادة واحدة. يقلل هذا النهج من استدعاءات الرسم، ويحسن أداء العرض، ويسهل المهام مثل تطبيق الظلال حسب المادة.

## كيف يقلل التقسيم من استدعاءات الرسم؟

يقوم تقسيم الشبكة بإنشاء شبكة فرعية واحدة لكل مادة، مما يسمح لمحرك الرسوميات بإصدار استدعاء رسم واحد لكل مادة بدلاً من استدعاء لكل مضلع. عدد أقل من استدعاءات الرسم يعني تغييرات حالة GPU أقل، مما يترجم مباشرة إلى معدلات إطارات أعلى على كل من بطاقات الرسوميات المكتبية وGPUات المحمولة المحدودة.

## لماذا تقسيم الشبكة حسب المادة؟

تقسيم الشبكة حسب المادة يحسن الأداء لأن المرسوم يمكنه تجميع استدعاءات الرسم لكل مادة، مما يقلل من تغييرات حالة GPU. كما يمنح المطورين مرونة لتطبيق ظلال مميزة، وتأثيرات ما بعد المعالجة، أو منطق تصادم لكل مادة. بالإضافة إلى ذلك، تكون الشبكات الفرعية الأصغر أسهل في البث، وإدارة الذاكرة، وإزالة غير المرئية، وهو أمر ذو قيمة خاصة على المنصات المحمولة، والواقع المعزز (AR)، والواقع الافتراضي (VR).

## الفوائد الكمية لـ Aspose.3D

Aspose.3D يدعم **أكثر من 30 صيغة إدخال وإخراج**—بما في ذلك OBJ وFBX وSTL وGLTF—ويمكنه معالجة الشبكات التي تحتوي على **ما يصل إلى 10 مليون مضلع** دون تحميل الملف بالكامل إلى الذاكرة. استخدام سياسة التقسيم `COMPACT_DATA` يمكن أن يقلل من استهلاك ذاكرة الرؤوس **بنسبة تصل إلى 40 %**، وهو أمر ذو قيمة خاصة لرسومات Java 3D على الأجهزة منخفضة الأداء.

## استيراد الحزم

الفئة `Scene` تمثل حاوية مشهد ثلاثي الأبعاد، بينما `Mesh` يحمل بيانات الهندسة؛ `VertexElementMaterial` يخزن مؤشرات المادة لكل مضلع، و`PolygonModifier` يوفر أدوات لتعديل الشبكة.  
```java
import com.aspose.threed.*;

import java.util.Arrays;
```

## دليل خطوة بخطوة

فيما يلي استعراض مختصر لكل خطوة، مع شروحات تسبق العنصر النائب لتعرف بالضبط ما يحدث.

### الخطوة 1: إنشاء شبكة لصندوق

الفئة `Box` تنشئ هندسة مكعب بستة أوجه، كل وجه يُمثل كمضلع منفصل. نبدأ ببدائية هندسية بسيطة—صندوق—حتى نتمكن من رؤية بوضوح كيف يحصل كل وجه (سطح) على مادته الخاصة لاحقًا.  
```java
// ExStart:SplitMeshbyMaterial

// Create a mesh of a box (composed of 6 planes)
Mesh box = (new Box()).toMesh();
```

### الخطوة 2: إنشاء عنصر مادة

`VertexElementMaterial` يخزن مؤشرات المادة لكل مضلع. من خلال ربطه بالشبكة، يمكننا التحكم بالمادة التي يستخدمها كل وجه.  
```java
// Create a material element on the box mesh
VertexElementMaterial mat = (VertexElementMaterial) box.createElement(VertexElementType.MATERIAL, MappingMode.POLYGON, ReferenceMode.INDEX);
```

### الخطوة 3: تحديد مؤشرات مادة مختلفة

هنا نعيّن مؤشر مادة فريد لكل من السطوح الستة للصندوق. ترتيب المصفوفة يتطابق مع ترتيب المضلعات التي يولدها البدائي `Box`.  
```java
// Specify different material indices for each plane
mat.setIndices(new int[]{0, 1, 2, 3, 4, 5});
```

### الخطوة 4: تقسيم الشبكة إلى شبكات فرعية

تُحدد تعداد `SplitMeshPolicy` كيفية معالجة بيانات الرؤوس أثناء التقسيم، مثل `CLONE_DATA` أو `COMPACT_DATA`. استدعاء `PolygonModifier.splitMesh` مع `SplitMeshPolicy.CLONE_DATA` ينشئ شبكة فرعية جديدة لكل مؤشر مادة مميز مع الحفاظ على بيانات الرؤوس الأصلية.  
```java
// Split the mesh into 6 sub-meshes, each plane becoming a sub-mesh
Mesh[] planes = PolygonModifier.splitMesh(box, SplitMeshPolicy.CLONE_DATA);
```

### الخطوة 5: تحديث مؤشرات المادة وإعادة التقسيم

لإظهار استراتيجية تقسيم مختلفة، نقوم الآن بتجميع السطوح الثلاثة الأولى تحت المادة 0 والبقية تحت المادة 1، ثم نقسم باستخدام `COMPACT_DATA` لإزالة الرؤوس غير المستخدمة.  
```java
// Update material indices and split into 2 sub-meshes
mat.getIndices().clear();
mat.setIndices(new int[]{0, 0, 0, 1, 1, 1});
planes = PolygonModifier.splitMesh(box, SplitMeshPolicy.COMPACT_DATA);
```

### الخطوة 6: تأكيد النجاح

رسالة بسيطة في وحدة التحكم تخبرك بأن العملية اكتملت دون أخطاء.  
```java
// Display success message
System.out.println("\nSplitting a mesh by specifying the material successfully.");
// ExEnd:SplitMeshbyMaterial
```

## تقليل استدعاءات الرسم وتحسين أداء العرض

من خلال تحويل كل مادة إلى شبكة خاصة بها، يمكنك تمكين خط أنابيب الرسوميات من إصدار استدعاء رسم واحد لكل مادة بدلاً من استدعاء لكل مضلع. هذا التقليل في استدعاءات الرسم يترجم مباشرة إلى معدلات إطارات أكثر سلاسة، خاصة على الأجهزة منخفضة الأداء. بالإضافة إلى ذلك، سياسة `COMPACT_DATA` تزيل الرؤوس غير المستخدمة، مما يقلل من عرض النطاق الترددي للذاكرة ويساعد GPU على العرض بكفاءة أكبر.

## المشكلات الشائعة والحلول

| المشكلة | سبب حدوثها | الحل |
|-------|----------------|-----|
| **الشبكات الفرعية تحتوي على رؤوس مكررة** | استخدام `CLONE_DATA` ينسخ جميع بيانات الرؤوس لكل شبكة فرعية. | التبديل إلى `COMPACT_DATA` عندما تريد إلغاء تكرار الرؤوس المشتركة. |
| **تعيين مادة غير صحيح** | طول مصفوفة المؤشرات لا يتطابق مع عدد المضلعات. | تحقق من عدد المضلعات (مثلاً، الصندوق يحتوي على 6) وقدم مصفوفة مؤشرات مطابقة. |

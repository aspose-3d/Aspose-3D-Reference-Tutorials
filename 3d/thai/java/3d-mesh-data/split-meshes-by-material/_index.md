# วิธีแยกเมชตามวัสดุใน Java ด้วย Aspose.3D

## บทนำ

หากคุณทำงานกับกราฟิก 3 มิติใน Java คุณจะพบว่า การประมวลผลเมชขนาดใหญ่สามารถเป็นคอขวดด้านประสิทธิภาพ—โดยเฉพาะเมื่อเมชเดียวมีหลายวัสดุ **การเรียนรู้วิธีแยกเมช** ตามวัสดุช่วยให้คุณแยกกลุ่มโพลิกอนที่ใช้วัสดุเดียวกันออกจากกัน ทำให้การเรนเดอร์เร็วขึ้น การคัลลิงง่ายขึ้น และควบคุมการจัดการเทกซ์เจอร์ได้ละเอียดขึ้น ในบทเรียนนี้เราจะอธิบายขั้นตอนที่ต้องทำ **การแยกเมชตามวัสดุ** ด้วยไลบรารี Aspose.3D พร้อมคำอธิบายเชิงปฏิบัติ เคล็ดลับการลด draw calls และคำแนะนำเพื่อปรับปรุงประสิทธิภาพการเรนเดอร์

## คำตอบอย่างรวดเร็ว
- **อะไรหมายถึง “split mesh by material”?** มันจะแยกเมชเดียวออกเป็นหลาย sub‑meshes, แต่ละอันประกอบด้วยโพลิกอนที่ใช้วัสดุเดียวกัน  
- **ทำไมต้องใช้ Aspose.3D?** มันให้ API ระดับสูง, ข้ามแพลตฟอร์ม ที่แยกไฟล์ฟอร์แมตระดับล่างออกโดยยังคงประสิทธิภาพ  
- **ใช้เวลานานเท่าไหร่ในการทำการทำงาน?** ประมาณ 10–15 นาทีของการเขียนโค้ดและทดสอบ  
- **ต้องการไลเซนส์หรือไม่?** มีรุ่นทดลองฟรี; ต้องมีไลเซนส์เชิงพาณิชย์สำหรับการใช้งานในผลิตภัณฑ์  
- **รองรับเวอร์ชัน Java ใด?** Java 8 หรือสูงกว่า  

## อะไรคือการแยกเมช?

`Mesh splitting` คือกระบวนการแบ่งเมช 3 มิติที่ซับซ้อนออกเป็นชิ้นย่อยที่จัดการได้ง่ายขึ้น เมื่อการแยกทำตามวัสดุ แต่ละ sub‑mesh ที่ได้จะมีโพลิกอนที่อ้างอิงวัสดุเดียวเท่านั้น วิธีนี้ช่วยลด draw calls, ปรับปรุงประสิทธิภาพการเรนเดอร์, และทำให้การใช้เชดเดอร์ต่อวัสดุเป็นเรื่องง่ายขึ้น

## การแยกเมชช่วยลด draw calls อย่างไร?

การแยกเมชสร้าง sub‑mesh หนึ่งชุดต่อวัสดุ ทำให้เอนจินกราฟิกสามารถส่ง draw call เพียงครั้งเดียวต่อวัสดุแทนที่จะส่งต่อโพลิกอนแต่ละอัน จำนวน draw call ที่ลดลงหมายถึงการเปลี่ยนสถานะ GPU น้อยลง ซึ่งแปลเป็นอัตราเฟรมที่สูงขึ้นบน GPU ทั้งแบบเดสก์ท็อปและมือถือที่มีข้อจำกัด

## ทำไมต้องแยกเมชตามวัสดุ?

การแยกเมชตามวัสดุช่วยเพิ่มประสิทธิภาพเพราะเรนเดอร์สามารถจัดกลุ่ม draw call สำหรับแต่ละวัสดุได้ ลดการเปลี่ยนสถานะของ GPU นอกจากนี้ยังให้ความยืดหยุ่นในการใช้เชดเดอร์ที่แตกต่าง, เอฟเฟกต์หลังการประมวลผล, หรือโลจิกการชนต่อวัสดุ อีกทั้ง sub‑mesh ที่เล็กลงง่ายต่อการสตรีม, การจัดการหน่วยความจำ, และการคัลลิง ซึ่งมีคุณค่าอย่างยิ่งบนแพลตฟอร์มมือถือ, AR, และ VR

## นำเข้าแพ็กเกจ

`Scene` เป็นอ็อบเจ็กต์รากของ Aspose.3D ที่เก็บโหนด, แสง, และกล้องทั้งหมดในฉาก 3 มิติ  
`Mesh` แสดงข้อมูลเรขาคณิต—เวอร์เท็กซ์, เอดจ์, และเฟซ—ของอ็อบเจ็กต์ 3 มิติ  
`VertexElementMaterial` เก็บดัชนีวัสดุแบบจำนวนเต็มสำหรับแต่ละโพลิกอน เพื่อให้สามารถกำหนดวัสดุตามโพลิกอนได้  
`PolygonModifier` มีเมธอดสเตติกสำหรับแก้ไขเมช เช่น การแยกหรือรวมโพลิกอน  

คลาส `Scene` เป็นคอนเทนเนอร์ของฉาก 3 มิติ, `Mesh` เก็บข้อมูลเรขาคณิต; `VertexElementMaterial` เก็บดัชนีวัสดุตามโพลิกอน, และ `PolygonModifier` ให้ยูทิลิตี้สำหรับการจัดการเมช  
```java
import com.aspose.threed.*;

import java.util.Arrays;
```

## คู่มือขั้นตอนต่อขั้นตอน

ต่อไปนี้เป็นการอธิบายสั้น ๆ ของแต่ละขั้นตอน พร้อมคำอธิบายก่อนโค้ดเพื่อให้คุณเข้าใจว่ากำลังทำอะไร

### ขั้นตอนที่ 1: สร้างเมชของกล่อง

คลาส `Box` สร้างเรขาคณิตรูปกล่องที่มีหกหน้า, แต่ละหน้าเป็นโพลิกอนแยกกัน เราเริ่มด้วย primitive ง่าย ๆ เพื่อให้เห็นว่าหน้าแต่ละหน้า (plane) จะได้รับวัสดุของตนเองอย่างไรต่อไป  
```java
// ExStart:SplitMeshbyMaterial

// Create a mesh of a box (composed of 6 planes)
Mesh box = (new Box()).toMesh();
```

### ขั้นตอนที่ 2: สร้างอิลิเมนต์วัสดุ

`VertexElementMaterial` เก็บดัชนีวัสดุสำหรับแต่ละโพลิกอน โดยการผูกกับเมช เราสามารถควบคุมว่าแต่ละหน้าใช้วัสดุใด  
```java
// Create a material element on the box mesh
VertexElementMaterial mat = (VertexElementMaterial) box.createElement(VertexElementType.MATERIAL, MappingMode.POLYGON, ReferenceMode.INDEX);
```

### ขั้นตอนที่ 3: ระบุดัชนีวัสดุต่าง ๆ

ที่นี่เรากำหนดดัชนีวัสดุที่ไม่ซ้ำกันให้กับแต่ละหน้า 6 ของกล่อง ลำดับของอาเรย์ตรงกับลำดับของโพลิกอนที่สร้างโดย primitive `Box`  
```java
// Specify different material indices for each plane
mat.setIndices(new int[]{0, 1, 2, 3, 4, 5});
```

### ขั้นตอนที่ 4: แยกเมชเป็น sub‑meshes

enum `SplitMeshPolicy` กำหนดวิธีการจัดการข้อมูลเวอร์เท็กซ์ระหว่างการแยก เช่น `CLONE_DATA` หรือ `COMPACT_DATA` การเรียก `PolygonModifier.splitMesh` พร้อม `SplitMeshPolicy.CLONE_DATA` จะสร้าง sub‑mesh ใหม่สำหรับแต่ละดัชนีวัสดุที่แตกต่างกันโดยคงข้อมูลเวอร์เท็กซ์เดิมไว้  
```java
// Split the mesh into 6 sub-meshes, each plane becoming a sub-mesh
Mesh[] planes = PolygonModifier.splitMesh(box, SplitMeshPolicy.CLONE_DATA);
```

### ขั้นตอนที่ 5: อัปเดตดัชนีวัสดุและแยกอีกครั้ง

เพื่อสาธิตกลยุทธ์การแยกแบบอื่น เราจะจัดกลุ่มสามหน้าแรกเป็นวัสดุ 0 และอีกสามหน้าเป็นวัสดุ 1 แล้วแยกด้วย `COMPACT_DATA` เพื่อลบเวอร์เท็กซ์ที่ไม่ได้ใช้ออก  
```java
// Update material indices and split into 2 sub-meshes
mat.getIndices().clear();
mat.setIndices(new int[]{0, 0, 0, 1, 1, 1});
planes = PolygonModifier.splitMesh(box, SplitMeshPolicy.COMPACT_DATA);
```

### ขั้นตอนที่ 6: ยืนยันความสำเร็จ

ข้อความคอนโซลง่าย ๆ จะบอกคุณว่าการดำเนินการเสร็จสมบูรณ์โดยไม่มีข้อผิดพลาด  
```java
// Display success message
System.out.println("\nSplitting a mesh by specifying the material successfully.");
// ExEnd:SplitMeshbyMaterial
```

## ลด draw calls และปรับปรุงประสิทธิภาพการเรนเดอร์

โดยการทำให้แต่ละวัสดุเป็นเมชของตนเอง คุณทำให้ pipeline กราฟิกส่ง draw call เพียงครั้งเดียวต่อวัสดุแทนที่จะเป็นต่อโพลิกอน การลด draw call นี้แปลเป็นอัตราเฟรมที่ราบรื่นขึ้นโดยเฉพาะบนฮาร์ดแวร์ระดับล่าง นอกจากนี้นโยบาย `COMPACT_DATA` ยังลบเวอร์เท็กซ์ที่ไม่ได้ใช้ ลดแบนด์วิธของหน่วยความจำและช่วยให้ GPU เรนเดอร์ได้อย่างมีประสิทธิภาพมากขึ้น

## ปัญหาทั่วไปและวิธีแก้

| ปัญหา | สาเหตุ | วิธีแก้ |
|-------|--------|----------|
| **Sub‑meshes contain duplicate vertices** | การใช้ `CLONE_DATA` คัดลอกข้อมูลเวอร์เท็กซ์ทั้งหมดสำหรับแต่ละ sub‑mesh | เปลี่ยนเป็น `COMPACT_DATA` เมื่อคุณต้องการให้เวอร์เท็กซ์ที่ใช้ร่วมกันถูกลบซ้ำ |
| **Incorrect material assignment** | ความยาวของอาเรย์ดัชนีไม่ตรงกับจำนวนโพลิกอน | ตรวจสอบจำนวนโพลิกอน (เช่น กล่องมี 6) และให้อาเรย์ดัชนีที่ตรงกัน |

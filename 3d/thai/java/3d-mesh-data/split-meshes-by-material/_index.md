# วิธีแยกเมชตามวัสดุใน Java ด้วย Aspose.3D

## บทนำ

หากคุณทำงานกับกราฟิก 3 มิติใน Java คุณจะพบว่าการประมวลผลเมชขนาดใหญ่สามารถเป็นคอขวดด้านประสิทธิภาพ—โดยเฉพาะเมื่อเมชเดียวมีหลายวัสดุ **การเรียนรู้วิธีแยกเมช** ตามวัสดุช่วยให้คุณแยกกลุ่มโพลิกอนที่ใช้วัสดุเดียวออกจากกัน ทำให้การเรนเดอร์เร็วขึ้น, การคัลลิงง่ายขึ้น, และควบคุมการจัดการเทกซ์เจอร์ได้ละเอียดมากขึ้น ในบทแนะนำนี้เราจะเดินผ่านขั้นตอนที่แน่นอนเพื่อ **แยกเมชตามวัสดุ** ด้วยไลบรารี Aspose.3D พร้อมคำอธิบายเชิงปฏิบัติ, เคล็ดลับการลด draw calls, และคำแนะนำในการปรับปรุงประสิทธิภาพการเรนเดอร์

## คำตอบอย่างรวดเร็ว
- **หมายถึงอะไรเมื่อพูดว่า “แยกเมชตามวัสดุ”?** มันแยกเมชเดียวออกเป็นหลายซับเมช, แต่ละซับเมชมีโพลิกอนที่ใช้วัสดุเดียวกัน  
- **ทำไมต้องใช้ Aspose.3D?** มันให้ API ระดับสูง, ข้ามแพลตฟอร์ม ที่ทำให้ซ่อนรายละเอียดไฟล์ระดับต่ำในขณะที่ยังคงประสิทธิภาพ  
- **ใช้เวลานานเท่าไหร่ในการทำการติดตั้ง?** ประมาณ 10–15 นาทีของการเขียนโค้ดและทดสอบ  
- **ต้องการไลเซนส์หรือไม่?** มีรุ่นทดลองฟรี; ต้องมีไลเซนส์เชิงพาณิชย์สำหรับการใช้งานในผลิตภัณฑ์  
- **รองรับเวอร์ชัน Java ใด?** Java 8 หรือสูงกว่า  

## การแยกเมชคืออะไร?

`Mesh splitting` คือกระบวนการแบ่งเมช 3 มิติที่ซับซ้อนออกเป็นชิ้นส่วนที่เล็กลงและจัดการได้ง่ายขึ้น เมื่อการแยกทำตามวัสดุ, แต่ละซับเมชที่ได้จะมีโพลิกอนที่อ้างอิงวัสดุเดียวเท่านั้น วิธีนี้ช่วยลดการเรียกวาดภาพ, ปรับปรุงประสิทธิภาพการเรนเดอร์, และทำให้การใช้เชดเดอร์ตามวัสดุง่ายขึ้น

## การแยกเมชช่วยลดการเรียกวาดภาพอย่างไร?

การแยกเมชสร้างซับเมชหนึ่งชุดต่อวัสดุ ทำให้เอนจินกราฟิกสามารถออกคำสั่ง draw call เพียงหนึ่งครั้งต่อวัสดุแทนที่จะเป็นหนึ่งครั้งต่อโพลิกอน การลดจำนวน draw calls ทำให้การเปลี่ยนสถานะ GPU น้อยลง ซึ่งแปลตรง ๆ เป็นอัตราเฟรมที่สูงขึ้นบน GPU เดสก์ท็อปและ GPU มือถือที่มีข้อจำกัด

## ทำไมต้องแยกเมชตามวัสดุ?

การแยกเมชตามวัสดุช่วยเพิ่มประสิทธิภาพเพราะเรนเดอร์สามารถจัดกลุ่ม draw call สำหรับแต่ละวัสดุได้, ลดการเปลี่ยนสถานะ GPU นอกจากนี้ยังให้ความยืดหยุ่นในการใช้เชดเดอร์ที่แตกต่าง, เอฟเฟกต์ post‑processing, หรือโลจิกการชนตามวัสดุ อีกทั้งซับเมชที่เล็กลงง่ายต่อการสตรีม, การจัดการหน่วยความจำ, และการคัลลิง ซึ่งมีคุณค่าอย่างยิ่งบนมือถือ, AR, และ VR

## ประโยชน์ที่วัดได้ของ Aspose.3D

คลาส `Scene` แสดงถึงคอนเทนเนอร์ของฉาก 3 มิติ, ส่วน `Mesh` เก็บข้อมูลเรขาคณิต; `VertexElementMaterial` เก็บดัชนีวัสดุตามโพลิกอน, และ `PolygonModifier` มียูทิลิตี้สำหรับการจัดการเมช.  
```java
import com.aspose.threed.*;

```

## คู่มือขั้นตอนต่อขั้นตอน

ด้านล่างเป็นการเดินผ่านสั้น ๆ ของแต่ละขั้นตอน, พร้อมคำอธิบายก่อนโค้ด placeholder เพื่อให้คุณทราบว่ากำลังเกิดอะไรขึ้น

### ขั้นตอนที่ 1: สร้างเมชของกล่อง

คลาส `Box` สร้างเรขาคณิตกล่องที่มีหกหน้า, แต่ละหน้าเป็นโพลิกอนแยกกัน เราเริ่มด้วย primitive เรขาคณิตง่าย ๆ — กล่อง — เพื่อให้เห็นชัดว่าแต่ละหน้า (plane) จะได้รับวัสดุของตนเองต่อไป  
```java
// ExStart:SplitMeshbyMaterial

// Create a mesh of a box (composed of 6 planes)
Mesh box = (new Box()).toMesh();
```

### ขั้นตอนที่ 2: สร้างองค์ประกอบวัสดุ

`VertexElementMaterial` เก็บดัชนีวัสดุสำหรับแต่ละโพลิกอน โดยการแนบเข้ากับเมช เราสามารถควบคุมว่าหน้าใดใช้วัสดุใด  
```java
// Create a material element on the box mesh
VertexElementMaterial mat = (VertexElementMaterial) box.createElement(VertexElementType.MATERIAL, MappingMode.POLYGON, ReferenceMode.INDEX);
```

### ขั้นตอนที่ 3: ระบุดัชนีวัสดุต่าง ๆ

ที่นี่เรากำหนดดัชนีวัสดุที่ไม่ซ้ำกันให้กับหกหน้าแต่ละหน้าของกล่อง ลำดับของอาร์เรย์ตรงกับลำดับของโพลิกอนที่สร้างโดย primitive `Box`  
```java
// Specify different material indices for each plane
mat.setIndices(new int[]{0, 1, 2, 3, 4, 5});
```

### ขั้นตอนที่ 4: แยกเมชเป็นซับเมช

enum `SplitMeshPolicy` กำหนดวิธีจัดการข้อมูลเวอร์เท็กซ์ระหว่างการแยก, เช่น `CLONE_DATA` หรือ `COMPACT_DATA`. การเรียก `PolygonModifier.splitMesh` พร้อม `SplitMeshPolicy.CLONE_DATA` จะสร้างซับเมชใหม่สำหรับแต่ละดัชนีวัสดุที่แตกต่างโดยคงข้อมูลเวอร์เท็กซ์เดิมไว้  
```java
// Split the mesh into 6 sub-meshes, each plane becoming a sub-mesh
Mesh[] planes = PolygonModifier.splitMesh(box, SplitMeshPolicy.CLONE_DATA);
```

### ขั้นตอนที่ 5: อัปเดตดัชนีวัสดุและแยกอีกครั้ง

เพื่อสาธิตกลยุทธ์การแยกที่ต่างออกไป, เราจะจัดกลุ่มสามหน้าแรกภายใต้วัสดุ 0 และอีกสามหน้าภายใต้วัสดุ 1, จากนั้นแยกด้วย `COMPACT_DATA` เพื่อลบเวอร์เท็กซ์ที่ไม่ได้ใช้  
```java
// Update material indices and split into 2 sub-meshes
mat.getIndices().clear();
mat.setIndices(new int[]{0, 0, 0, 1, 1, 1});
planes = PolygonModifier.splitMesh(box, SplitMeshPolicy.COMPACT_DATA);
```

### ขั้นตอนที่ 6: ยืนยันความสำเร็จ

ข้อความคอนโซลง่าย ๆ จะบอกคุณว่าการดำเนินการเสร็จสมบูรณ์โดยไม่มีข้อผิดพลาด  
```java
// Display success message
System.out.println("\nSplitting a mesh by specifying the material successfully.");
// ExEnd:SplitMeshbyMaterial
```

## ลดการเรียกวาดภาพและปรับปรุงประสิทธิภาพการเรนเดอร์

โดยการทำให้แต่ละวัสดุเป็นเมชของตนเอง, คุณทำให้ pipeline กราฟิกสามารถออกคำสั่ง draw call เพียงหนึ่งครั้งต่อวัสดุแทนที่จะเป็นหนึ่งครั้งต่อโพลิกอน การลด draw calls นี้แปลตรง ๆ เป็นอัตราเฟรมที่ราบรื่นขึ้น, โดยเฉพาะบนฮาร์ดแวร์ระดับล่าง นอกจากนี้นโยบาย `COMPACT_DATA` ยังลบเวอร์เท็กซ์ที่ไม่ได้ใช้, ลดแบนด์วิธของหน่วยความจำและช่วยให้ GPU เรนเดอร์ได้อย่างมีประสิทธิภาพมากขึ้น
